Monitoring & Observability

“If you’re not alarming on it, you don’t know about it.”

Metrics that matter

CategoryMetrics
Latencyorder-to-ack (p99, p999), feed-to-signal, signal-to-send
Executionfill rate by order type, slippage vs model, adverse fill rate, cancel-to-fill ratio
Riskposition delta, exposure, drawdown, margin utilization

If any of these spike and you have no alert — you’re flying blind.

Dead man’s switch

Heartbeat to a watchdog. If heartbeat stops, watchdog cancels all open orders and flattens. Not optional.

Observability as infrastructure

Observability lives in its own module, not scattered through business logic:

core/
strategy/
risk/
execution/
observability/    ← macros, metrics traits, middleware, tracing setup

Strategy imports a trait, not a logger. Business logic stays pure.

Use structured tracing, not debug logs

Instead of:

let start = Instant::now();
// do thing
println!("took {:?}", start.elapsed());

Use spans:

#[instrument]
async fn place_order(...) { ... }

Start/end time auto-recorded. Context preserved. No logic pollution. Export to Prometheus / Jaeger / OTLP.

Use middleware / wrappers

Instead of instrumenting call sites, wrap components:

struct TimedGateway<G> {
    inner: G,
}

Intercept send_order, cancel_order. Measure once inside wrapper. All strategies automatically instrumented. No duplication.

Event sourcing for free replay

Append every event to an event log with timestamps at ingestion and handling. Then you can:

  • Replay deterministically
  • Compute latency post-fact
  • Run offline analysis

No debug lines required. Just good architecture.

Reconciliation as continuous runtime

Next level beyond periodic REST snapshots:

  • Real-time checksum comparison
  • Balance delta validation per fill
  • Order state machine invariants

Reconciliation becomes part of runtime, not a cron job.

State is sacred

Local order book / position / balance state drifts silently from missed fills, partial executions, or exchange bugs. Pro setups:

  • Snapshot full account + open orders + positions via REST every few seconds
  • Delta-reconcile on every WebSocket update
  • If drift > epsilon (e.g., 0.1% on position), auto-flatten or pause
  • Log every correction with timestamps — audit trails save your ass in disputes

Measure, log, alert — then measure more

Every metric: latency histograms (p99/p999), slippage per trade, edge decay over time, reconciliation drift events. Alert on anomalies instantly. Post-mortems for every fat tail — “why did we miss that arb?” becomes your daily ritual.
