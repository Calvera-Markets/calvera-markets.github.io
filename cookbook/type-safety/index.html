Type Safety

The problem: currency amnesia

A naked Decimal carries no information about what it denominates. Is it USD? BTC? Basis points? Quantity? The compiler can’t tell, and neither can the person reading the code at 3am during an incident.

Unit errors in trading are catastrophic: confusing bid with ask, notional with quantity, USD with BTC. These bugs cause real losses.

Phantom types for currency safety

Zero-cost at runtime. The type parameter exists only for the compiler:

use std::marker::PhantomData;

struct USD;
struct BTC;

struct Amount<Currency> {
    value: Decimal,
    _currency: PhantomData<Currency>,
}

// Same currency: compiles
let a: Amount<USD> = Amount::new(dec!(100));
let b: Amount<USD> = Amount::new(dec!(50));
let c = a + b;  // OK

// Different currencies: compile error
let d: Amount<BTC> = Amount::new(dec!(0.5));
let e = a + d;  // ERROR — type mismatch

PhantomData<T> compiles away completely — zero runtime cost. You can’t accidentally add dollars to bitcoin. The compiler prevents it.

What stays plain Decimal

Not everything needs currency tagging. Dimensionless quantities stay as Decimal:

  • Rates, ratios, percentages
  • Basis points
  • Scores
  • Quantities (lots, contracts)
  • Leverage multipliers

The rule: if it has a unit of currency, tag it. If it’s a pure number, leave it.

Design space

Option A: Phantom types everywhere. Maximum safety but infects every function signature. Monomorphization bloat. Hard at FFI boundaries.

Option B: Phantom at leaf, runtime-tagged at boundaries. Use Amount<C> in homogeneous contexts (within a single exchange), DenominatedAmount at cross-exchange or serialization boundaries.

Option C: Runtime-tagged only. Simpler but gives up compile-time guarantees.

Option B is the sweet spot for most trading systems.

Boundary handling

At system boundaries (cross-exchange, user input, serialization):

struct DenominatedAmount {
    value: Decimal,
    currency: CurrencyId,
}

Convert to phantom-typed Amount<C> at the earliest opportunity. Convert back to DenominatedAmount at serialization boundaries.

OCaml heritage

“Rust is essentially OCaml’s type system with C++‘s performance.”

The phantom type pattern comes directly from ML-family languages where it’s used to encode domain invariants into types. Jane Street uses OCaml for exactly this reason — the type system catches entire categories of trading bugs at compile time.
